# Version 1.03-test2 — corrections de l'audit

Branche créée depuis `1.02` (commit `9b47c25`) après la revue des cinq versions
(`main` et `1.03-test1` pointaient alors sur le même commit initial `0f8cb9b`).
Cette version ne change aucun rendu visuel : elle sécurise la chaîne de production.
La feuille de route complète est dans [AMELIORATIONS.md](../../AMELIORATIONS.md).

## Corrections

### 1. Validation des scénarios avant rendu
Nouveau script `scripts/check/validate-scenarios.mjs`, commandes :

```powershell
npm run validate                 # tout le catalogue
npm run video -- validate heat   # une seule base
```

Contrôles (échec = code de sortie 1) : format vidéo, fichiers du catalogue,
chemins audio, scènes (bornes et ordre), beats (créneaux et longueur de phrase),
courbe de Chaleur strictement croissante, rappel des `"verify": true`.
La validation est lancée automatiquement avant `still`, `render` et `prepare`.

### 2. Cache d'ambiance par empreinte
Auparavant, les générateurs gardaient le WAV existant (`--if-missing`) : modifier un
scénario laissait une ambiance périmée. `scripts/project/video.mjs` calcule maintenant
une empreinte SHA-1 du scénario **et** du générateur (`.cache/ambience-hashes.json`) :
toute modification régénère l'ambiance concernée, sinon rien n'est relancé.

### 3. Scènes inconnues : échec explicite
`WhatIf.tsx` filtrait silencieusement les scènes absentes du registre — une faute de
frappe dans un `id` retirait une scène sans message. La composition lève maintenant
une erreur listant les identifiants inconnus (`end` restant un habillage reconnu).

### 4. Typage de `sampleNum`
`src/core/animation.ts` : la fonction devient générique (`<K extends {t: number}>`),
ce qui supprime le `as any` de `WhatIf.tsx` tout en restant compatible avec les
autres appels.
